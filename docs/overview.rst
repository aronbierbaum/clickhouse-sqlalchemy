.. _overview:

Overview
========

What is clickhouse-sqlalchemy?
------------------------------

**clickhouse-sqlalchemy** is a `SQLAlchemy <https://www.sqlalchemy.org>`_ dialect
for `ClickHouse <https://clickhouse.com>`_, the open-source column-oriented
database management system built for high-performance analytical queries.

It allows you to interact with ClickHouse using the familiar SQLAlchemy ORM and
Core APIs, so you can define models, compose queries, and manage schemas with
the same Python code you would write for any other SQLAlchemy-supported database.

Why use it?
-----------

- **Familiar API** — If you already use SQLAlchemy, no new query language to
  learn. Define tables, write queries, and manage schemas exactly as you would
  with PostgreSQL or MySQL.

- **ClickHouse-specific features** — The dialect exposes ClickHouse extensions
  that have no standard SQL equivalent, including table engines (MergeTree
  family, Distributed, Buffer, etc.), ``FINAL``, ``SAMPLE``, ``LIMIT BY``,
  ``ARRAY JOIN``, ``WITH TOTALS/ROLLUP/CUBE``, TTL expressions, and
  ClickHouse-specific JOIN strictness and distribution modifiers.

- **Multiple connection interfaces** — Connect to ClickHouse over its native
  binary TCP protocol (recommended, via ``clickhouse-driver``) or over HTTP
  (via ``requests``). Async support is also available via ``asynch``.

- **Schema migrations** — Works with `Alembic <https://alembic.sqlalchemy.org>`_
  for autogenerated, version-controlled schema migrations, including
  Materialized Views.

Architecture
------------

clickhouse-sqlalchemy is structured around SQLAlchemy's dialect system.
Each supported transport has its own driver:

+----------------+------------------+-----------------------------------------------+
| Interface      | Driver           | Description                                   |
+================+==================+===============================================+
| Native (TCP)   | ``native``       | Recommended. Uses ``clickhouse-driver``.      |
|                |                  | Supports all features including streaming and |
|                |                  | external tables.                              |
+----------------+------------------+-----------------------------------------------+
| Async Native   | ``asynch``       | Async variant of the native interface via     |
|                |                  | ``asynch``.                                   |
+----------------+------------------+-----------------------------------------------+
| HTTP           | ``http``         | Uses the ``requests`` library.                |
|                |                  | Simpler setup but fewer advanced features.    |
+----------------+------------------+-----------------------------------------------+

Use the ``clickhouse+<driver>://`` URL scheme to choose the interface:

.. code-block:: python

    # Native (recommended)
    engine = create_engine('clickhouse+native://user:password@host:9000/database')

    # HTTP
    engine = create_engine('clickhouse+http://user:password@host:8123/database')

Key capabilities
----------------

* **Table definition** — Both declarative (ORM) and Core ``Table`` styles.
* **ClickHouse table engines** — MergeTree, ReplicatedMergeTree, CollapsingMergeTree,
  SummingMergeTree, ReplacingMergeTree, AggregatingMergeTree, Distributed,
  Buffer, MaterializedView, Log, TinyLog, Memory, Null, File, and more.
* **DDL** — ``CREATE``/``DROP TABLE``, ``ON CLUSTER``, TTL, column codecs,
  ``DEFAULT``/``MATERIALIZED``/``ALIAS`` expressions.
* **DML** — Batch ``INSERT``, ``INSERT … SELECT``, ``ALTER UPDATE``,
  ``ALTER DELETE``.
* **SELECT extensions** — ``FINAL``, ``SAMPLE``, ``LIMIT BY``, ``ARRAY JOIN``,
  ``WITH CUBE``, ``WITH ROLLUP``, ``WITH TOTALS``, Lambda expressions.
* **JOIN enhancements** — type (INNER/LEFT/RIGHT/FULL/CROSS), strictness
  (OUTER/SEMI/ANTI/ANY/ASOF), and distribution (GLOBAL).
* **Reflection** — Reflect existing ClickHouse tables (including their engines)
  back into SQLAlchemy metadata.
* **Alembic integration** — Schema migration support including Materialized Views.
* **Execution options** — Pass ClickHouse server settings and external tables
  directly through SQLAlchemy's ``execution_options`` mechanism.
